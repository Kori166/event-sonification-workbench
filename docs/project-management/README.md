# Project Management Records

This directory contains the retained evidence used to plan, track and review the MSc project. The
records have distinct roles:

- [project-plan.md](project-plan.md): final staged project plan, principal milestones, scope and
  current completion status.
- [progress-log.md](progress-log.md): canonical chronological project-wide record of material work,
  decisions, problems, corrective actions and verification.
- [supervision-log.md](supervision-log.md): verified supervision feedback and resulting actions,
  including earlier meetings transcribed from retained researcher records.
- [risk-register.md](risk-register.md): project risks, mitigations and review status.
- [stage-1-checklist.md](stage-1-checklist.md): Stage 1 data ingestion and normalisation acceptance
  evidence.
- [stage-2-checklist.md](stage-2-checklist.md): Stage 2 cue, suppression and deterministic rendering
  acceptance evidence.
- [stage-3-checklist.md](stage-3-checklist.md): Stage 3 technical evaluation and reporting evidence
  acceptance evidence.
- [stage-4-checklist.md](stage-4-checklist.md): Stage 4 artefact, inspection and release acceptance
  evidence.
- [stage-4-progress-log.md](stage-4-progress-log.md): detailed supporting Stage 4 recovery,
  integration, correction and browser-acceptance history. It is not the primary project-wide log.

Final technical contracts are consolidated under [data-model](../data-model/). Canonical technical
evaluation evidence and audited reporting derivatives are retained under [evaluation](../evaluation/),
and significant methodological, technical and scope decisions are retained under
[decisions](../decisions/).

GitHub Issues, pull requests and commits retain lower-level implementation and review history. The
documents in this directory provide the marker-facing project-management hierarchy without
duplicating that engineering detail.
